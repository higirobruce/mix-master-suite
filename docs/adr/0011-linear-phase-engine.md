# ADR-0011: Linear-phase FIR engine (partitioned convolution, design, latency)

**Status:** Accepted (2026-11-03)

## Context

Spec: Linear-phase EQ "FIR via frequency sampling or windowed design; 2048–16384 taps; latency reported to host"; budget < 2.5 % per instance at 48 k / 64 samples; 64-bit FIR; latency 20–170 ms. Multiband's linear-phase mode (20+ ms) and a future convolution reverb want the same engine.

A direct-form FIR of 16384 taps costs 16384 multiply-adds per sample per channel (≈ 35 % of one core per instance at 48 k): out of the question. FFT convolution is the only route; the choice is the partition scheme and what it does to latency and precision.

## Decision

- **Uniform-partition overlap-save convolution in double precision** (`core/fir/PartitionedConvolver.h`). The impulse is cut into K = ⌈N / P⌉ partitions of P taps, each stored as its 2P-point spectrum. Input is collected into a P-sample FIFO; when it fills, the last 2P input samples are transformed once, multiplied-and-accumulated against the K partition spectra through a frequency-domain delay line (K spectra of the input's history), inverse-transformed, and the last P samples are the output block. The FFT is the engine's own radix-2 complex transform in double (JUCE's is float only), with the complex multiply-accumulate written on separate real / imaginary arrays so the compiler vectorises it.
- **The partition size P is the host block rounded up to a power of two, with a floor** (`minPartition`, a `prepare()` argument). The per-sample cost is ≈ 16 K flops for the accumulation plus 20 log₂(2P) for the transforms; at P = 64 and N = 16383, K = 256 and the engine alone spends the whole 2.5 % budget. The Linear-phase EQ prepares with a 512-sample floor (K ≤ 32: ≈ 1 % at 16384 taps), which adds 10.7 ms at 48 k to the FIR's own (N − 1) / 2 at every length.
- **Latency is P + (N − 1) / 2 samples**, reported through the base's `dspLatencySamples()`: the FIFO delays every sample by exactly P whatever the host's block schedule (so renders are bit-identical across block sizes, as the base checks require) and the symmetric impulse centres at (N − 1) / 2. P depends on the host block, so the reported latency is re-evaluated in `prepareToPlay`.
- **Design by frequency sampling** (`core/fir/LinearPhaseDesign.h`): the target is the product of the bands' biquad magnitudes |H_b(e^{jω})| (the same RBJ designs the Channel EQ runs, so a band in Minimum mode and the same band in Linear mode have the same magnitude), sampled on an L-point grid (L the requested FIR length, a power of two), made zero-phase (real, even), inverse-transformed and rotated to the centre; the N = L − 1 odd taps symmetric about (N − 1) / 2 are kept (the dropped tap is the farthest from the centre and negligible for a smooth target). The impulse gets a Tukey taper over its outer half: the targets are smooth, so the trigonometric interpolation between grid points is accurate wherever a feature spans a few bins and the resolved content, which lives near the centre, is untouched (≤ 0.015 dB measured); the taper only removes the truncation edge, so a band below the floor smears instead of ringing across the spectrum (0.57 → 0.13 dB above two floors, 0.015 above four). A full Kaiser window was measured and rejected: β = 8 costs up to 0.4 dB on resolved bands. Symmetry is enforced exactly (pairs averaged), so the phase is exactly linear.
- **Resolution floor:** the design is exact at the grid points fs / L apart and accurate between them where a feature spans several bins. `resolutionHz(taps, fs) = 2 fs / L` is the published floor; the response is guaranteed within ±0.1 dB only above twice it for bands whose corner is above twice it (4 fs / L: 94 Hz at 48 k for 2048 taps, 12 Hz for 16384), and the EQ's editor shows the floor. A band below the floor is rendered smeared (a +6 dB shelf at 30 Hz reads about +5 dB at DC with 2048 taps at 192 k) and leaves the response above four floors within 0.1 dB.
- Impulse changes are prepared off the audio thread (the design allocates) and swapped in by the plugin (ADR of the LP-EQ: two convolvers per path with a 20 ms crossfade). `setImpulse()` itself does not allocate and may be called on the audio thread with a precomputed impulse, but it recomputes K spectra (K FFTs of 2P): the plugin keeps that off the audio thread.

## Consequences

- Tests: the convolver against direct convolution < −120 dBFS for 1023 / 4097 / 16383 taps under a varying block schedule; the output impulse lands at `latencySamples()`; silence after reset. The design: no bands → a centred unit impulse; three bands at four rates within ±0.1 dB of the biquad product above twice the floor with phase linear within ±2°; exact symmetry.
- Latency exceeds the spec's 20–170 ms range by the partition (10.7 ms at the EQ's floor) — recorded for the reviewer; the alternative (P = 64) breaks the CPU budget at the longest FIR.
- Cost rows in the core benchmark: `convolver_4096`, `convolver_16384` at P = 512.
- Non-uniform partitioning (shorter head partitions for lower latency at the same cost) is the known next step if a 1 ms-latency linear-phase mode is ever wanted; it was not needed to meet the spec.
