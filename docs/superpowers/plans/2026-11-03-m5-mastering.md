# M5 Mastering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The mastering chain on the shared base: a linear-phase FIR engine and loudness / true-peak metering in `/core`, then Linear-phase EQ, Multiband compressor, Bus compressor, M/S processor, Soft clipper and True-peak limiter, each measured against the spec's gates, with the EBU Tech 3341/3342 vectors within ±0.1 LU / ±0.3 dBTP and the limiter never above its ceiling by more than 0.1 dBTP on the test set.

**Architecture:** Two new core areas: `core/fir` (uniform-partition FFT convolver in 64-bit, linear-phase magnitude design by frequency sampling) and `core/metering/{LoudnessMeter,TruePeakMeter}` (BS.1770-4 K-weighting with gating, Tech 3342 LRA, 4× polyphase true-peak). Each plugin is a composition on `mm::PluginProcessorBase` / `mm::gui::PluginEditorBase` of existing modules (`LinkwitzRiley`, `Detector`, `GainComputer`, `EnvelopeFollower`, `SidechainFilter`, `Lookahead`, `Oversampler`, `ADAA`, `MatchedBiquad`) plus the new ones. The mastering family uses `accents::mastering`.

**Tech Stack:** as M0–M4 (C++20, JUCE 8, Catch2, Python harness with numpy / scipy / pyloudnorm, `mm_render` offline host, `module:` registry for reference renders). `juce::dsp::FFT` for the convolver.

**Spec:** `docs/SPEC.md` (Mastering plugins table; Technical requirements rows Linear-phase EQ … Limiter; Testing and validation rows True-peak accuracy, Aliasing, Null, Dynamics; UI/UX rows EQs, Compressors / limiter, Multiband, Imager / M/S), `CLAUDE.md` M5 exit criteria ("Linear-phase FIR engine, Linear-phase EQ, Multiband comp, Bus comp, M/S processor, Soft clipper, True-peak limiter. EBU Tech 3341/3342 vectors within ±0.1 LU and ±0.3 dBTP; limiter never exceeds ceiling by more than 0.1 dBTP on the test set."), roadmap `2026-11-01-suite-roadmap.md` M5 (T1–T9).

## Global Constraints

- Budgets (tools/budgets.json, 100 instances at 48 k / 64, limits scale by the runner factor, min of 3 runs): lp_eq < 2.5 %, multiband_comp < 1.5 %, bus_comp < 0.5 %, ms_processor < 0.5 %, soft_clipper < 1.5 %, limiter < 2.5 %.
- Latency (spec table): LP-EQ 20–170 ms (= (N−1)/2 of the FIR, reported, changes when the length changes); Multiband 0 (minimum-phase LR4); Bus comp 0 (2× oversampling optional: its latency reported when on); M/S 0; Soft clipper ~1–2 ms (oversampler latency); Limiter 1–10 ms lookahead + oversampling, reported.
- Precision: LP-EQ FIR and the multiband crossovers in 64-bit; M/S filters 64-bit (matched biquads); the rest 32-bit float.
- Nonlinear stages oversampled (hard rule 3): clipper 4×/8×, limiter's true-peak detection 4×; aliasing at 19 kHz < −80 dBFS with oversampling on, asserted at each stage's reference drive as in M3 (ADR-0006 ruling), full-drive floors recorded.
- Null tests: LP-EQ flat < −120 dBFS; M/S encode/decode < −120 dBFS; dynamics at 1:1 / threshold max < −90 dBFS; frequency response within ±0.1 dB / ±2° where a transfer curve exists (the LP-EQ above its resolution floor f_res = 2·fs/N, stated in the test).
- Dynamics: attack / release within 10 % of the label; ratio within 0.1. Every continuous parameter smoothed; stepped and switch parameters change coefficients only (no click above 1.5× the input's own sample jump on a change while running, as in M3/M4).
- Sample rates 44.1 / 48 / 96 / 192 k for every response, metering and limiter-ceiling test; FIR taps, K-weighting, true-peak filter and crossovers re-derived on a rate change (`check_sr_change_mid_stream`).
- ADRs before code: ADR-0011 linear-phase engine, ADR-0012 limiter. The plan's other topologies are recorded in the ADR of the plugin they belong to as amendments only where a decision deviates from the spec table.
- params.json is the single source; `tools/gen_params.py` must regenerate without drift; every plugin ≥ 8 factory presets; fuzz entries in `tests/plugins/test_stability.py` (`MAX_STATIC_GAIN_DB`, `PURE_GAIN`, `PURE_GAIN_BASE`).

## Review Focus

1. Limiter fed inter-sample peaks (a 0.45·fs tone burst at +3 dBFS, square waves, the EBU TP vectors) with the ceiling at −1 dBTP: output true-peak ≤ −0.9 dBTP at every rate, including the first block after `reset()` and across a release tail. Test: `test_limiter_ceiling_never_exceeded` (Task 8).
2. LP-EQ FIR length changed while audio runs (2048 → 16384): the reported latency changes once, the host hears no click above 1.5× the input's own sample jump, and the band curve is unchanged after the switch. Test: `test_lp_eq_length_change_no_click` (Task 3).
3. Loudness meter at 44.1 / 96 / 192 k: the K-weighting is re-derived (the BS.1770 coefficients are given at 48 k) so every synthetic 3341 vector reads −23.0 ± 0.1 LUFS at each rate. Test: `test_lufs_synthetic_vectors_4_rates` (Task 2).
4. Multiband crossovers dragged past each other (low above high) while a tone runs: the plugin enforces order (low ≤ high − 1/3 oct), the sum stays flat and nothing clicks. Test: `test_mb_crossover_order_enforced` (Task 4).
5. Bus compressor stepped attack switched 0.1 → 30 ms and ratio 2 → 10 during gain reduction: coefficient change only, no sample jump above 1.5× the input's own; and the 2× oversampling switch reports its latency change. Test: `test_bus_comp_switches_no_click` (Task 5).
