# M1 Core DSP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every shared DSP module the 16 plugins compose (filters, dynamics, smoothing, metering, delay, oversampling, nonlinear/ADAA) exists in `mm_core`, with Catch2 unit tests, Python frequency/step-response measurements through `mm_render --module`, and a 44.1/48/96/192 kHz matrix on each; linear modules null below −120 dBFS.

**Architecture:** Header-only templates in `core/` (namespace `mm`), `float` for processing and `double` for coefficient design and 64-bit filter paths. Each module is registered in `mm_render`'s `ModuleRegistry` so the Python suite measures the exact code the plugins will run. Analytic reference curves come from each design's own transfer function (`evaluate`) so tests prove implementation against design; analog-match tolerances are reported separately.

**Tech Stack:** C++20, JUCE 8 (`juce::dsp::Oversampling`, `juce::dsp::FFT` only), Catch2 v3, numpy/scipy, `mm_render`.

**Spec:** `docs/SPEC.md` (Shared foundation table; Testing and validation gates), `CLAUDE.md` (M1 exit criteria; hard rules 1–3), roadmap `2026-11-01-suite-roadmap.md` (Core Interfaces section: the signatures below repeat it and are normative).

## Global Constraints

- Exit criteria (CLAUDE.md M1): "filters (biquad, matched, FIR, Linkwitz–Riley), dynamics core, smoothing, metering FIFO, delay line, oversampling, nonlinear/ADAA. Each with unit tests, frequency/step-response measurement tests, sample-rate matrix. Null test residual < −120 dBFS for linear modules."
- Spec gates used here: frequency response within ±0.1 dB and ±2° of the analytic curve, 20 Hz–20 kHz; dynamics attack/release within 10%, ratio within 0.1; alias products below −80 dBFS at 19 kHz with oversampling on; parameter smoothing 20–50 ms default; nonlinear stages always paired with oversampling; oversampling latency reported.
- Hard rules: no allocation after `prepare`; every module tested at 44.1k, 48k, 96k, 192k; no NaN/denormal.
- Measurement band for the ±0.1 dB / ±2° check: 20 Hz to `min(20 kHz, 0.45·fs)`.

## Review Focus

1. Filter parameters modulated every sample (EQ node drags, LFOs) → no instability or blow-up. Test: `svf modulation stability` (Task 5), `biquad coefficient update stability` (Task 3).
2. Extreme Q / frequency at the edges (Q 0.1 and 10, f = 20 Hz and 0.49·fs) → finite, bounded response. Tests: `*_edge_params` in Tasks 3, 4, 5, 8.
3. Delay time changed abruptly → no discontinuity beyond interpolation. Test: `fractional delay time slew` (Task 11).
4. Lookahead/oversampling latency reported equals measured. Tests: `lookahead latency` (Task 10), `oversampler latency` (Task 12).
5. ADAA with near-identical consecutive samples (DC, very low frequencies) → no division blow-up. Test: `adaa ill-conditioned fallback` (Task 13).
