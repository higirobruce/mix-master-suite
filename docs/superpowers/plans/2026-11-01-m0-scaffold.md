# M0 Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A repo where one Utility plugin builds as VST3, AU, CLAP and Standalone (AAX stubbed), passes pluginval level 10 on macOS, Windows and Linux in CI, and where every later plugin inherits parameters-from-JSON, gain-matched bypass, trim, state, presets, metering and the shared chrome from a base it does not have to rewrite.

**Architecture:** Root CMake with SHA-pinned FetchContent (JUCE 8, clap-juce-extensions, Catch2). `tools/gen_params.py` turns `plugins/<name>/params.json` into `Params.h` and `tool_schema.json` at configure time. `mm_core` holds the first DSP primitives, `mm_plugin_base` the JUCE processor base, `mm_gui` the shared chrome. `mm_render` is a JUCE console host that renders plugins and core modules offline for the Python measurement suite. CI runs build, ctest, pytest, pluginval and the CPU benchmark on three OSes.

**Tech Stack:** C++20, JUCE 8.0.x, clap-juce-extensions, Catch2 v3, CMake ≥ 3.25, Ninja, Python 3.11 + uv, numpy/scipy/soundfile/pyloudnorm/pytest, pluginval, clap-validator, GitHub Actions.

**Spec:** `docs/SPEC.md` (Shared foundation, Technical requirements, Testing and validation, UI/UX), `CLAUDE.md` (hard rules, M0 exit criteria), roadmap `docs/superpowers/plans/2026-11-01-suite-roadmap.md` (Core Interfaces section is normative for names).

## Global Constraints

See roadmap "Global Constraints". For M0 specifically:
- Utility: CPU < 0.1% per instance (100 instances, 48 kHz, 64 samples); latency 0; no oversampling; 32-bit float; no sidechain. Parameters: gain ±24 dB, polarity flip L/R, L↔R swap, mono sum, DC block, phase rotation, channel mute.
- Null test at flat settings: residual below −120 dBFS.
- pluginval strictness level 10 passes for VST3 and AU (macOS) / VST3 (Windows, Linux); CLAP validated with clap-validator.
- Exit criteria (CLAUDE.md M0): repo layout, CMake, CI matrix green, Utility plugin builds in all formats, pluginval level 10 passes on macOS/Windows/Linux, ADR-0001 build system, ADR-0002 parameter model.

## Review Focus

1. Host sends a block larger than 0 but smaller than the prepared maximum, or 0 samples, between normal blocks → identical output to a single-block render. Test: `test_variable_block_sizes` (Task 8) and Catch2 `variable block sizes` (Task 5).
2. Silence or a DC offset after loud audio → no denormal slowdown, no NaN; DC removed when `dc_block` is on. Tests: `test_denormal_tail`, `test_dc_block` (Task 8).
3. Parameter snapped to min / max / default within one block → ramp over the smoothing time, no click. Test: `test_param_extremes` (Task 8), driven from `params.json`.
4. State saved by one format and loaded by another, or an older state missing a parameter → values identical / defaults filled / unknown ignored. Tests: Catch2 `state round trip`, `state forward compat` (Task 5); `test_state_roundtrip` (Task 8).
5. Mono, stereo and mono→stereo instances → accepted; 5.1 rejected; mono→stereo copies the processed mono to both outputs. Tests: Catch2 `bus layouts` (Task 5), `test_channel_configs` (Task 8).

- [ ] **Step 3: Implement the headers**

Smoother: linear ramp, `stepsRemaining`, `increment = (target-current)/steps`, `steps = max(1, round(rampMs*1e-3*sr))`.
